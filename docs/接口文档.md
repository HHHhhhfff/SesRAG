# SesRAG 接口文档

**版本**：v0.5（PRD-003／schema3 与三代兼容契约）
**状态**：v3 RAG资源／诊断／会话已接线并完成开发检查；真实模型计数及正式效果验收受限，见[PR-003](pr/003-SesRAG-RAG检索增强与MinerU接入-PR.md)。原v0.4及PRD-002验收记录仅说明历史基线，不能证明v0.3全部通过。
**日期**：2026-10-30
**适用范围**：`/api/v1`、`/api/v2`、`/api/v3` HTTP API、Run Event 查询和 SSE 投影；本轮变动与兼容规则以[第8节](#8-v03-rag-与-mineru接口)为准。

v1 会话保留旧路径和成功契约。当前工作台的Thread／Branch元数据和生成模型选择复用v2；消息、Run、事件、上下文与显式操作使用v3。v1会话创建仍写默认Branch，列表只返回`conversation_version=1`；v1不能投影schema2/3、v2不能投影schema3时，在owner校验后返回409 `API_VERSION_REQUIRED`。v3读取三代历史且不改写旧事件／引用；来源schema1/2缺少冻结语料视图时，v3 retry/regenerate明确拒绝，旧协议操作按原入口执行。取消按Run协议与持久事实处理。v1新消息仍遵守归档、Branch忙碌和原有幂等重放规则。

本文件是前端接口约定和当前实现的唯一说明来源。接口变更必须同时更新后端路由、契约、测试和本文件；根目录 `README.md` 只保留导航，不复制完整接口表。当前 Demo 使用固定 `OWNER_ID`（默认 `local-user`），尚未提供生产认证、RBAC 或多租户隔离。

## ADR-002 历史基线与证据边界（2026-10-13）

以下旧章节保留v1/v2基线；PRD-003引入的固定路由、DOCX写入升级、schema3守卫及新工作台调用方式覆盖其中同名旧描述，以第8节和实际版本化契约为准。PRD-002正式两轮完整HTTP/Event/生成类型校核见[历史测试报告](../tests/sesrag-persistent-session-workspace-test/测试报告.md)，小修另见[修复回归报告](../tests/sesrag-persistent-session-workspace-test/小缺陷修复与回归验收报告.md)。本轮没有调用或修改该验收工程。

当前正式对象契约包括 [Thread](../contracts/thread_v1.json)、[Message](../contracts/message_v1.json)、[Run/Task 摘要](../contracts/run_v1.json)、[Document](../contracts/document_v1.json)、[Health](../contracts/health_v1.json)、[引用兼容联合](../contracts/citation_v1.json) 和 [新 Evidence](../contracts/evidence_v1.json)；请求结果包装与错误结构集中在 [API 响应契约](../contracts/api_responses_v1.json)。前端使用 `npm run generate:api --prefix frontend` 生成类型，`npm run check:api --prefix frontend` 只读检查漂移。QLT动态门禁覆盖完整 HTTP 成功/校验/业务/基础设施错误矩阵与11类 Event type/data联合payload，并生成临时类型逐字比较；实际执行结果见本轮验收报告，不能把类型生成通过单独当作协议验收。

根 Compose 前端通过同源 Vite 代理访问 API；HTTP、SSE 和健康读取共用同一 base。前端只是持久事实的投影：状态事件触发重新读取 Run，终态再读取 Thread 和 Journal 后缀；断线不取消 Run，切 Thread/Run 时丢弃旧作用域返回。开发配置、重连与文档轮询预算见 [前端模块说明](../frontend/README.md)。

上传最多读取 10 MiB + 1 byte，超过返回 413 `DOCUMENT_TOO_LARGE` 且不创建文件或事实。
文件名先将 Windows/Unix 路径规范化为安全 basename，只保存逻辑文件名；最多 255 字符，
空名、冒号与控制字符返回 422 `INVALID_DOCUMENT_FILENAME`，UUID 存储路径独立于该名称。
存储失败返回 503 `DOCUMENT_STORAGE_FAILED`；数据库提交失败返回 503 `DOCUMENT_PERSIST_FAILED`，即使 rollback 再失败也独立尝试清理本次 UUID 文件。清理失败返回 503 `DOCUMENT_CLEANUP_FAILED`，仅清理本次拥有目标，不删除共享根或他人文件。
相同 Document 的活动索引请求复用同一 Task；失败重建保留旧 active 批次。

新生成引用遵循 `contracts/evidence_v1.json`：包含 `index_batch_id` 和 `locations`。
locations 是原文的 1 起算行号（txt/md）或段落号（docx），含该基础段落的字符范围；
chunk 的 `start_offset/end_offset` 独立表示切分范围（0 起算、右端不含），不可当作行号。
旧索引迁移后 `locations=[]`，旧 Message/Journal 不重写。retrieval.completed.items 同时携带批次和基础位置。

索引永久错误：`DOCUMENT_ENCODING_INVALID`、`DOCUMENT_PARSE_FAILED`、`DOCUMENT_SOURCE_MISSING`、
`EMPTY_DOCUMENT`、`DOCUMENT_PARSE_LIMIT`。解析子进程 30 秒超时为 `DOCUMENT_PARSE_TIMEOUT`，不可自动重试。
真正空文本失败；非空空白文本保留字符切分索引行为。子进程创建失败为可重试 `DOCUMENT_PARSER_UNAVAILABLE`；输入、ZIP展开/条目、位置和输出字节均有上限，超限统一 `DOCUMENT_PARSE_LIMIT`。
Provider 400/401/403 等非暂态 HTTP 错误使用 `PROVIDER_HTTP_<status>` 永久失败；429、408、5xx 和
`PROVIDER_TRANSPORT_ERROR`/`PROVIDER_TIMEOUT` 可重试。畸形响应、空内容和超限分别为
`PROVIDER_INVALID_RESPONSE`、`PROVIDER_EMPTY_CONTENT`、`PROVIDER_RESPONSE_LIMIT`；
向量契约要求 384 个有限且 float32 可表示的数字，维度/数值错误（含超大 JSON 整数）为 `EMBEDDING_DIMENSION_MISMATCH` 或 `EMBEDDING_INVALID`。Provider 使用从请求开始到响应头和响应体的总60秒预算以及4MiB响应字节上限；
检索 K 必须为正整数（`INVALID_TOP_K`）。所有消息为固定安全摘要，不公开上游响应、路径或凭据。

## 1. 通用约定

- 正式业务接口前缀为 `/api/v1`；健康检查保留在 `/health/live` 和 `/health/ready`。
- 请求和普通响应使用 JSON；上传文档使用 `multipart/form-data`，字段名为 `file`。
- 请求校验失败返回 HTTP `422` 和非空 `detail` 数组（`ValidationErrorResponse`）。每项仅包含安全 `type`、`loc` 和固定 `msg="请求参数校验失败"`，不返回原始输入、异常正文、`input`、`ctx` 或 `url`；`loc` 只保留服务端已知字段路径与数字位置，未知字段表示为 `field`。业务 `ApplicationError` 的 422/404/503 等仍使用下述 `code/message` 契约。
- 时间使用 ISO 8601 格式。ID 由服务端生成，客户端不得伪造状态、事件序号、租约代数或最终消息 ID。
- Message 的 `source` 为 `user_input` 或 `assistant_generation`，不能用 role 推断来源；Message 公开 `created_at`。Document 的 `source` 为安全逻辑来源，Demo 上传固定为 `local_upload`，不公开宿主路径或 storage key。
- 应用层错误统一返回：

  ```json
  {"code": "STABLE_ERROR_CODE", "message": "可供开发者诊断的消息"}
  ```

- `POST /api/v1/threads/{thread_id}/messages` 支持可选 `Idempotency-Key` 请求头。同一 Thread 使用相同 Key 会返回已有 Message/Run/Task，不重复创建用户消息；不同 Thread 或不同 Key 不共享幂等结果。

### 3.1 Event envelope

查询接口中的每个 Event 和 SSE `data` 使用同一结构，并符合 [`contracts/run_event_v1.json`](../contracts/run_event_v1.json)：

```json
{
  "schema_version": 1,
  "event_id": "uuid",
  "run_id": "uuid",
  "seq": 3,
  "type": "retrieval.completed",
  "occurred_at": "2026-10-05T00:00:00Z",
  "data": {"count": 0, "items": []}
}
```

当前事件类型包括 `run.created`、`task.queued`、`task.leased`、`run.started`、`retrieval.completed`、`answer.delta`、`task.retry_scheduled`、`message.completed`、`run.succeeded`、`run.failed` 和 `run.cancelled`。同一 Run 的 `seq` 严格递增，Event 只追加不更新。

`task.leased` 与领取事实同事务提交，包含 `task_id/worker_id/generation/attempt`。最终 `message.completed`、`run.succeeded`、assistant Message 和 Task/Run 状态在同事务提交；失败和取消均只有一个有效终态，不追加旧执行者迟到增量。重试到期 Task 回 queued，Run 保持 retry_waiting，重新开始执行才回 running；前端不得由 Task queued 推断 Run 已改变状态。

SSE 每条消息使用 `id: <seq>`、`event: <type>` 和 JSON `data`。客户端重连时优先发送最后收到的 `Last-Event-ID`；服务端将其作为 `after_seq`。客户端必须按 `seq` 去重，并只在 `run.succeeded`、`run.failed` 或 `run.cancelled` 后结束观察。断开连接本身不表示取消。

SSE 保持首版兼容游标规则：Header 优先于 query，负数或无法解析的 `Last-Event-ID` 归 0，未发送 Header 使用 query（负数归 0）。普通 `/events` 的 query 输入由接口校验，负数或非整数返回 422；不把普通查询规则强加到 SSE Header。不存在或不可访问的 Run 在发送流前返回 404；终态游标之后没有新事件时有界关闭空连接。

PostgreSQL 是 Event Journal 的事实来源。Redis 仅用于通知“可能有新事件”，通知丢失时数据库轮询仍应补齐事实；前端不得依据 Redis payload 或本地状态宣布终态。

## 6. 兼容与变更规则

1. 新增字段优先保持向后兼容；改变状态、字段含义、Event 类型或终态语义时，先更新对应 PRD/ADR 和契约。
2. 破坏性接口变更使用新的 API 或契约版本，不在旧路径上增加隐式双读双写。
3. Event 的 `schema_version` 与 JSON Schema 同步递增；旧 Event 必须仍可按原版本补放，除非有明确迁移方案。
4. 前端类型、API client 和 SSE 解析器必须与本文件及 `contracts/` 同步；手工维护的重复接口表不具有权威性。

## 7. ADR-002 v2 契约基线

2026-10-24工作台归档呈现补齐：侧栏普通/已归档视图共享 `GET /api/v2/threads?include_archived=true` 的全量排序游标，在客户端按 `archived_at` 投影已加载摘要。`include_archived=true` 仍表示包含归档，并非仅归档；接口字段、HTTP版本和Event版本不变。有效归档偏好可恢复只读详情，归档/取消归档进入目标视图；空视图且有后续页提示继续加载。

本节按 [PRD-002](prd/002-SesRAG-持久化会话与对话工作台-PRD.md) 和 [ADR-002 §5～6](adr/002-sesrag-persistent-session-workspace-implementation-plan.md) 固定已接线的后端接口。JSON 真源为 `contracts/*_v2.json`，请求/包装集中于 `api_responses_v2.json#/$defs`；后端 DTO 在 `backend/api/schemas/v2/`，生成类型为 `frontend/src/types/api-v2.ts`。

### 7.1 路由、请求与成功响应

下表路径均以 `/api/v2` 开头，共 15 个方法/路径，不增加 archive、documents、index、health 别名。对象直接返回时不额外套 `data` 字段。

| 方法 | 路径 | 请求/查询 | 成功响应契约 |
| --- | --- | --- | --- |
| GET | `/models` | 无 | 200 `ModelListResponse` |
| GET | `/threads` | `ThreadListQuery` | 200 `ThreadList` |
| POST | `/threads` | `ThreadCreate` | 201 `thread_v2`，默认 Branch 同事务创建 |
| GET | `/threads/{thread_id}` | `ThreadDetailQuery` | 200 `ThreadDetail` |
| PATCH | `/threads/{thread_id}` | `ThreadPatch` | 200 `thread_v2` |
| GET | `/threads/{thread_id}/branches` | 无 | 200 `BranchListResponse` |
| POST | `/threads/{thread_id}/branches` | `BranchCreate` | 首次 201 / 幂等复用 200，直接返回 `branch_v2` |
| POST | `/threads/{thread_id}/messages` | `MessageCreate` | 首次 201 / 复用 200 `MessageRunResponse` |
| GET | `/runs/{run_id}` | 无 | 200 `run_v2` |
| GET | `/runs/{run_id}/events` | `EventListQuery` | 200 `EventListResponse` |
| GET | `/runs/{run_id}/events/stream` | `after_seq`、`Last-Event-ID` | 200 SSE，data 为 `run_event_v2` |
| POST | `/runs/{run_id}/cancel` | 无 body | 200 `CancelResponse` |
| POST | `/runs/{run_id}/retry` | 可省略 body，等价 `{}`；`RunOperationCreate` | 首次 201 / 复用 200 `MessageRunResponse` |
| POST | `/runs/{run_id}/regenerate` | 同 retry | 首次 201 / 复用 200 `MessageRunResponse` |
| GET | `/runs/{run_id}/context` | `ContextQuery` | 200 `ContextResponse` |

所有 v2 JSON 请求禁止额外字段，owner、operation_kind、parent_run_id、状态、消息/任务结果身份由服务端控制。`ThreadCreate.title` 可省略，默认“新会话”；title 首尾修剪后 1～200 字符。`ThreadPatch` 至少提供 title 或 archived，archived 是布尔值；显式 null 无效。`BranchCreate` 必须提供 parent_branch_id/fork_message_id；name 可省略由服务端命名，传入则修剪后 1～80 字符且不得为 null。分叉身份归属与路径由业务层验证。

`MessageCreate` 必须提供 branch_id、content、expected_version（非负整数）。正文保留原始首尾空白，限制 1～20,000 字符且不能全空白。可选 model_profile_id（1～100 字符）和 model_profile_version（正整数）必须同时提供，显式 null 无效。未传采用服务端默认 Profile。retry/regenerate 仅接收同一对显式 Profile 字段，默认复制来源版本；legacy 来源必须显式选择，缺失返回业务 422 `MODEL_PROFILE_REQUIRED`。客户端不得伪造 operation_kind/parent_run_id。

仅创建 Thread 不要求幂等键。创建分支/消息/retry/regenerate 必须提供非空 `Idempotency-Key`；缺失为请求校验 422。Thread 内同键同规范请求复用结果，同键异内容为 409 `IDEMPOTENCY_CONFLICT`。请求指纹区分“未传默认 Profile”与显式选择，不随着默认项变化重算。只创建 Branch 不伪造 Message/Run/Task 身份。

### 7.2 确定的响应包装与分页

| 导出名 | 精确字段 |
| --- | --- |
| ThreadList | `{threads: ThreadSummary[], next_cursor: string\|null, has_more: boolean}` |
| ThreadDetail | `{thread, branch, branch_path: Branch[], messages: Message[], runs: RunSummary[], active_run_id: string\|null, recent_run_id: string\|null, next_before_seq: integer\|null, has_more: boolean}` |
| BranchListResponse | `{branches: Branch[]}` |
| MessageRunResponse | `{branch_id, message_id, run_id, task_id, status}`；显式重试/重生成的 message_id 是复用的用户输入 |
| CancelResponse | `{run_id, status}`，状态允许 cancelling |
| EventListResponse | `{events: RunEvent[], next_after_seq: integer, has_more: boolean}` |
| ModelListResponse | `{models: ModelProfile[], default_profile: {profile_id, version}}` |
| ContextResponse | 未规划 `{plan:null, reason:"not_planned"}`；已规划 `{plan:ContextPlan, reason:null}` |

Thread 列表按 `(updated_at DESC, thread_id DESC)` 排序，include_archived 默认 false，limit 默认 50、范围 1～200。cursor 是服务端生成的无填充 base64url UTF-8 JSON `[updated_at,thread_id]`（时间为 UTC ISO8601）；无更多页时 next_cursor=null。非法 cursor 是请求校验 422，不接受客户端修改排序和 owner。

详情 branch_id 省略取默认，branch_path 为根至所选 Branch 的有序祖先链。before_seq 为正整数，读取该路径上 `seq < before_seq` 的最近 limit 条；默认/最大为 50/200，返回 messages 按 seq 升序。还有旧消息时 next_before_seq 为本页最小 seq，否则 null；空页不产生游标。runs 仅包含本页用户输入或 assistant 产出相关的 Run 摘要，另用 active_run_id/recent_run_id 定位所选 Branch 的活动/最近 Run，即使该 Run 不在本页也不丢失恢复入口。

events.after_seq 默认 0、必须为非负整数；limit 默认 200、范围 1～1000。按 Run 内全局 seq 升序返回 `seq > after_seq`；next_after_seq 是本页最后 seq，空页保持请求 after_seq；has_more 表示仍有后续持久事件。SSE Header 优先，负数/不可解析游标归 0；SSE 内循环沿相同分页游标追平。断线只停止观察；终态且无后缀时有界关闭，不伪造终态。ContextQuery.generation 省略取最新，显式值必须为正整数，指定不存在代数返回 404。

### 7.3 对象投影和安全字段

ThreadSummary 保留 owner/title/archived_at/created_at/updated_at，并增加 default_branch_id 和 conversation_version（1/2）。Branch 固定返回 branch_id、thread_id、parent_branch_id、fork_message_id、name、is_default、head_message_id、version、created_at、updated_at；根分支 parent/fork 同为 null。Message 增加不可变创建 branch_id；run_id 是最初创建者，不能用它推断用户输入只被执行一次，执行输入真源是 Run.user_message_id。Message.seq 仍是 Thread 全局序号，分支路径可不连续；citations 直接复用 citation_v1，新的生成输出仍须验证完整 evidence_v1。

ThreadSummary.title 是原样持久化字符串，允许 legacy 空字符串、纯空白和首尾空白；列表、详情和元数据修改响应均不得修剪、回退或隐式重命名旧标题。即使仅归档等元数据修改使 conversation_version 从1升到2，也保持原值。§7.1 的修剪后1～200字符非空规则仅约束新的v2创建和显式重命名请求，响应不复用该请求类型。

RunSummary 返回 run_id、branch_id、user_message_id、assistant_message_id、parent_run_id、operation_kind、execution_schema_version、status、created_at。operation_kind 为 initial/user_retry/regenerate/branch_continue；RunStatus 为 queued/running/retry_waiting/cancelling/succeeded/failed/cancelled。RunDetail 额外含 thread_id、legacy、model_profile_id/version、model、snapshot、context_plan、task、last_error_code、cancel_requested_at、updated_at。task 严格复用 v1 TaskSummary，cancelling 只属于 Run。

model 是冻结的安全 ModelSelection：profile_id、version、display_name、provider_kind（mock/openai_compatible）、model_name、context_window_tokens、max_output_tokens。`GET /api/v2/models` 由 ModelProfile 元数据表读取，返回安全展示字段、availability reason 和唯一启用默认的成对身份；不会在启动时导入 JSON。snapshot 只含 schema_version=2、prompt_version、context_policy_version、summary_policy_version、counter_version、context_window_tokens、reserved_output_tokens、safety_margin_tokens、retrieval_enabled、retrieval_top_k、embedding_dimensions=384。不得直接返回 snapshot_json。context_plan 是安全 ContextPlanSummary：context_plan_id、generation、attempt、status、四项预算、selected_message_count、omitted_message_count、summary_count。legacy Run 必须 legacy=true，model_profile_id/version、model、snapshot、context_plan 全为 null；不得输出 cancelling，不伪造模型或历史计划。新 Run legacy=false、模型与快照非空，尚未规划的 context_plan=null。

真实OpenAI-compatible Profile必须配置显式tiktoken；Mock词法计数不能用于真实Profile。服务端私有retrieval快照另冻结Embedding kind、无凭据地址、模型和受信Secret alias，恢复不读取当前Settings覆盖；这些内部字段不因此新增到公开snapshot中。Key值仅运行时解析，不出现在上述对象投影中。

模型列表在 ModelSelection 上增加 status、reason、is_default。status 为 enabled/disabled/invalid；enabled 的 reason=null，其他状态 reason 为 MODEL_PROFILE_DISABLED/MODEL_PROFILE_INVALID/MODEL_CREDENTIAL_UNAVAILABLE 等既定安全码且 is_default=false。default_profile 明确返回唯一启用默认的 profile_id/version，对同 ID 多版本不能按 ID 合并。base_url、generation_params、tokenizer_config、config_ref 和凭据均不公开；运行时失效不能静默换模型。

ContextPlan 返回执行/归属/锚点 ID、selected_message_ids、omitted_messages（message_id/reason）、omitted_ranges（from_seq/to_seq/count/reason）、summaries（安全来源元数据）、selected_evidence（v1 RetrievalItem 身份加 content_hash）、trim_policy_version、counter_version、四项预算、status、created_at。四项预算为 estimated_input_tokens、reserved_output_tokens、safety_margin_tokens、context_window_tokens；status=ready/budget_exceeded。候选 ID/范围/摘要/证据数组有界为 200，窗口外历史只存范围与数量。范围仅供展示，真实路径身份仍由消息 ID 保留。SummaryMetadata 只含 summary_id/thread_id/branch_id、covered_message_ids、from_seq/to_seq、source_hash、source_segments（message_id/start_offset/end_offset）、summary_policy_version、source_run_id、created_at。hash 为 SHA256 小写 64 位；位置为右端不含字符偏移。不返回 Prompt、summary_text、证据原文、Secret 或宿主路径。

### 7.4 事件两代严格联合

`run_event_v2.json` 顶层 oneOf 的第一分支直接引用原封不动的 run_event_v1；第二分支只允许 schema_version=2。旧事件不回写、不补 task 字段、不按同名事件猜协议。schema 2 envelope 保持 event_id/run_id/seq/type/occurred_at/data，seq 全 Run 单调增加，不随 attempt/generation 重置。

每个 schema 2 data 均要求 task_id、attempt、generation。下表“执行”表示 task_id 非空、attempt/generation 正整数；“控制”允许 null，已有但未领取的 attempt/generation 可以为 0。事件所有额外字段都拒绝，包括未知嵌套 Secret。

| type | 身份 | 除共同身份外的 data 必填字段 |
| --- | --- | --- |
| run.created | 控制 | message_id、branch_id、operation_kind |
| task.queued | 控制 | 无 |
| task.leased | 执行 | worker_id |
| run.started | 执行 | 无 |
| retrieval.completed | 执行 | count、items（直接引用 v1 RetrievalItem，无 filename） |
| answer.delta | 执行 | text |
| task.retry_scheduled | 执行 | error_code |
| message.completed | 执行 | message_id、citations（直接引用 citation_v1） |
| run.succeeded | 执行 | message_id |
| run.failed | 控制 | error_code；规划/领取前失败可空身份 |
| run.cancelled | 控制 | reason 固定 user_requested |

| context.compacted | 执行 | summary（SummaryMetadata） |

retry_created/regenerated 只写新 Run Journal，不向已终态旧 Run追加。独立 Branch 创建没有 RunEvent。执行代码负责使用真实领取身份填充，事件结构不能替代租约条件更新。

### 7.5 错误、状态和 v1 兼容

错误真源复用 api_responses_v1 的 ErrorResponse/ValidationErrorResponse。所有接口请求字段/类型/范围/必填失败 422 为安全 detail 数组；业务错误（包括业务 422）为 code/message。v2 `UnprocessableResponse` 是这两种精确结构的 oneOf，不按 HTTP422 独断错误来源。owner 不符/对象不存在先返回 404；业务冲突为 409；基础设施故障为安全 503。

| 场景/稳定码 | HTTP/结果 |
| --- | --- |
| API_VERSION_REQUIRED、LEGACY_RUN_ACTIVE | 409，版本入口或旧活动 Run 阻止升级 |
| THREAD_ARCHIVED、BRANCH_BUSY、BRANCH_HEAD_CHANGED、IDEMPOTENCY_CONFLICT | 409，归档/活动执行/乐观版本/幂等冲突 |
| MODEL_PROFILE_UNAVAILABLE | 409 业务冲突，显式 Profile 不可用于新 Run；不回退默认模型 |
| MODEL_PROFILE_REQUIRED、BRANCH_LIMIT_EXCEEDED | 422 业务错误，legacy 操作缺模型或分支限额 |
| 非法父路径/分叉点 | 422 业务错误，安全 code/message |
| 指定不存在的 Context generation | 404 |
| CONTEXT_TOO_LARGE、INVALID_RUN_SNAPSHOT、MODEL_CREDENTIAL_UNAVAILABLE | 异步 Run 失败及安全 error_code，不撤销先前 201 |
| RUN_EVENT_LIMIT、ANSWER_LIMIT_EXCEEDED、DELTA_BUFFER_LIMIT | 异步资源上限失败；保留唯一 run.failed，失败 draft 不创建 assistant Message |
| MODEL_EMPTY_OUTPUT、MODEL_STREAM_INVALID | 异步模型空输出或协议失败，不能作为成功回答 |

已执行 Task 的取消响应先为 `cancelling`；继续观察同一 Run 的 Journal/GET，直到有效 Worker 或租约回收器写 `cancelled`，客户端不得根据计时器自行终结。自动重试保持 Run/Task/input 身份，并以新的 generation/attempt 追加事件和不可变 ContextPlan；每代 draft 单独显示。`GET /context` 在未规划时是 `{plan:null,reason:"not_planned"}`，指定不存在 generation 为业务404。计划只公开身份/hash/范围/预算，完整 Prompt 和 summary_text 不提供。摘要提取故障的有效计划策略是 `trim_only_v1`，安全诊断码 `SUMMARY_EXTRACTION_FAILED` 仅写关联结构化日志；TokenCounter/mandatory 故障不会被该回退吞掉。候选窗口外省略以安全 seq 范围/计数展示，失败/取消的无完整轮次输入使用 `incomplete_turn`。

v1 的九个会话入口原路径、请求及成功结构均保留（§2 五个、§3 四个）；v0.3 的 documents/index 写入边界见 §8，health 保持原契约。v1 Thread 列表仅返回 conversation_version=1；v1 访问 version2 Thread 或 schema2 Run 返回409 API_VERSION_REQUIRED。owner 校验先于版本检查。旧 Run 即使 Thread 已升级，仍能从 v1 GET/Event/SSE/cancel；v2 可读取/取消旧 Run，不升级 Thread，旧事件原样补放。v1 默认 Branch 同样限制一个活动 Run，冲突明确 BRANCH_BUSY。

v2 新建 Thread 为 version2。旧 Thread 的 GET、Event、SSE、cancel 不推进 conversation_version；首次 PATCH/创建 Branch/消息/retry/regenerate 在同一事务内检查不存在活动 legacy Run后升级到2，失败全回滚且不自动降回1。API 路径、conversation_version、execution_schema_version 和 Event.schema_version 是四个独立维度，不重标旧事实。旧 v1 client 和 api.ts 公共导出保持兼容；v0.3 工作台使用下述 v3 会话事实协议，并复用 v2 元数据接口。

## 8. v0.3 RAG 与 MinerU接口

外部重排服务401/403记录`RERANK_AUTH_FAILED`，认证／权限和`PROFILE_UNAVAILABLE`安全禁用错误不允许dense降级；安全状态在后续外发阶段前重新检查。`unknown_may_continue`的历史解析终态不因stage为stopped而绕过新重建操作的重复成本确认。

本节对应 PRD-003/ADR-003，版本 v0.3。DTO 真源为 `backend/api/schemas/v3/`，以 `backend.tools.export_rag_contracts` 导出至 `contracts/`，前端从 JSON Schema 生成 `api-v3.ts`。下面列的是新增 v3 路径；v2 Thread/Branch/Models 的元数据 CRUD 保留原路径。请求未说明的额外字段拒绝，公开响应不含 Secret、服务端地址、storage key、签名 URL 或原始上游响应。

`rag_summary.execution_state=not_started|running|completed|failed|cancelled`；`result_mode=null|off|ok|empty|degraded`。关闭RAG为off，无伪造ToolCall；预算先失败时保持not_started并显示真实预算错误；empty仅表示成功空检索。只有配置为dense_fallback且重排服务／协议／输入预算失败时可degraded，Embedding／权限／视图错误不降级。

### 8.3 引用、位置和工具事件

新增`rag.search@1`是固定只读工具，不接受任意代码、owner、URL或SQL。每Task/generation最多一个逻辑ToolCall；新代保留旧调用的failed/cancelled/interrupted事实。诊断与Run共用检索服务，诊断不宣布Run终态。

schema3新事件增加`tool.started/tool.stage/tool.completed/tool.failed/tool.cancelled`，data带call_id、execution_id、tool_version、stage和执行身份；结束另含安全mode/count/error_code。`retrieval.completed`含count、execution_id、mode、bundle_ids。schema3 `message.completed`使用Citation v2。其他生命周期／delta／context事件沿用原语义；所有seq在同Run严格递增，终态和最终消息保持同事务提交。

Message的`citation_schema_version=1|2`决定数组分支。Citation v2包含schema_version=2、bundle_id、document_id、index_batch_id、context_evidence_ids、locations、dense_score及rerank_score；只引用当前ContextPlan真正选入范围。Evidence Bundle的components提供component/chunk身份、规范区间和hash。候选trace的`rerank_input_start/end`是候选文本内0起算、右端不含的实际重排前缀；与模型最终上下文选择区间不同。

位置区间按Unicode字符、0起算、右端不含；源行／段／页号1起算。`origin=source|normalized`，`quality=verified|block_only|unavailable`；kind支持line/paragraph/page/slide/sheet_range/table_cell/block。只有可可靠映射的PDF原页才标page；Word转换分页、缺失的PPT幻灯片号或Excel范围不伪造。当前这些不可靠来源显示规范block。重建后旧引用仍指旧批次，源文本缺失则明确不可读取。

### 8.4 兼容与错误

v1/v2严格Schema不添加新字段。v2 Thread创建／列表／改名／归档、Branch CRUD、Models列表继续复用。Thread首次有schema3 Run后，v2详情和新消息写入返回409 `CLIENT_UPGRADE_REQUIRED`；v3详情读全历史。原v1布局版本检查仍有效。旧Run仍通过原版本读取，不因同Thread有新Run而重标事件。v1/v2不能读schema3详情／事件，v2取消可共享取消逻辑。

v1文档白名单仍为旧三格式读视图；txt/md写入依赖可信旧384空间，DOCX上传／index在写任何新事实前返回409 `DOCUMENT_WRITE_UPGRADE_REQUIRED`，其他新办公格式不被旧接口接受。新UI使用v3。未知旧空间返回 `LEGACY_RAG_SPACE_UNAVAILABLE`，不猜维度来源、不把新空间冒充旧空间。

| 场景 | 结果 |
| --- | --- |
| 缺失／非法幂等键、授权缺失、参数非法 | 422，稳定code/message或已有安全detail；不回显输入 |
| 同键异内容、同名库、活动构建／分支冲突 | 409，相应稳定冲突码 |
| MinerU关闭／缺Key／未验证格式，真实模型输入计数未核实 | 409及MINERU_*／INPUT_COUNTER_UNVERIFIED；没有远端任务 |
| 类型／MIME不匹配、超限源 | 415／413；安全错误，无可用候选 |
| 异步解析／向量／rerank／取消／截止失败 | 已受理HTTP状态不撤销；由Build／Execution／Run的state及error_code投影 |
| 未知提交 | MINERU_SUBMISSION_UNKNOWN；本地failed、may_continue、不自动重提 |
| 清理后的临时诊断／Bundle | 三十天墓碑期410 RAG_RESOURCE_EXPIRED；之后404，其他owner始终404 |
| 对象不存在／越权 | 404，不泄漏存在性 |

健康接口仍以PG／Redis／Worker原契约为准；MinerU或真实模型不可用不使本地文本／聊天全局不可启动。真实服务启用与升级／清理步骤见[v0.3 Runbook](runbooks/rag-v3-development.md)。
