# SesRAG 接口文档

**版本**：v0.1
**状态**：当前 Demo 正式接口说明
**日期**：2026-10-05
**适用范围**：`/api/v1` HTTP API、Run Event 查询和 SSE 投影

本文件是前端接口约定和当前实现的唯一说明来源。接口变更必须同时更新后端路由、契约、测试和本文件；根目录 `README.md` 只保留导航，不复制完整接口表。当前 Demo 使用固定 `OWNER_ID`（默认 `local-user`），尚未提供生产认证、RBAC 或多租户隔离。

## 1. 通用约定

- 正式业务接口前缀为 `/api/v1`；健康检查保留在 `/health/live` 和 `/health/ready`。
- 请求和普通响应使用 JSON；上传文档使用 `multipart/form-data`，字段名为 `file`。
- 时间使用 ISO 8601 格式。ID 由服务端生成，客户端不得伪造状态、事件序号、租约代数或最终消息 ID。
- 应用层错误统一返回：

  ```json
  {"code": "STABLE_ERROR_CODE", "message": "可供开发者诊断的消息"}
  ```

- `POST /api/v1/threads/{thread_id}/messages` 支持可选 `Idempotency-Key` 请求头。同一 Thread 使用相同 Key 会返回已有 Message/Run/Task，不重复创建用户消息；不同 Thread 或不同 Key 不共享幂等结果。

## 2. Thread 和 Message

| 方法 | 路径 | 请求 | 成功响应 | 说明 |
| --- | --- | --- | --- | --- |
| `POST` | `/api/v1/threads` | `{ "title": "可选标题" }` | `201`，Thread 摘要 | 创建当前 owner 的 Thread；标题默认为“新会话”。 |
| `GET` | `/api/v1/threads` | 无 | `200`，Thread 摘要数组 | 按更新时间倒序返回当前 owner 的 Thread。 |
| `GET` | `/api/v1/threads/{thread_id}` | 无 | `200`，`thread`、`messages`、`runs` | 返回会话事实，不依赖浏览器本地缓存。 |
| `POST` | `/api/v1/threads/{thread_id}/archive` | 无 | `200`，`{thread_id, archived}` | 写入归档时间；当前 Demo 不删除历史。 |
| `POST` | `/api/v1/threads/{thread_id}/messages` | `{ "content": "问题正文" }` | 首次 `201`，幂等重复 `200`；返回 `message_id`、`run_id`、`task_id`、`status` | 在同一事务中追加用户 Message、创建 Run/Task 和初始 Event。 |

`content` 长度为 1～20,000 个字符。Run 创建成功后由 Worker 异步执行，Message 创建接口不会等待模型回答。

## 3. Run、Event 和取消

| 方法 | 路径 | 查询/请求 | 成功响应 | 说明 |
| --- | --- | --- | --- | --- |
| `GET` | `/api/v1/runs/{run_id}` | 无 | `200`，Run 摘要和 Task 摘要 | 返回当前 Run 状态、assistant Message ID、Task attempt/generation/lease 和错误码。 |
| `GET` | `/api/v1/runs/{run_id}/events` | `after_seq`，默认 `0` | `200`，`{"events": [...]}` | 返回 `seq > after_seq` 的事件，按 `seq` 升序。 |
| `GET` | `/api/v1/runs/{run_id}/events/stream` | `after_seq` 可选；支持 `Last-Event-ID` | `text/event-stream` | 先补放数据库事件，再持续轮询 Event Journal；收到终态 Event 后结束。 |
| `POST` | `/api/v1/runs/{run_id}/cancel` | 无 | `200`，`{run_id, status}` | 持久化取消请求并通知 Worker；已处于终态的 Run 保持原状态。 |

### 3.1 Event envelope

查询接口中的每个 Event 和 SSE `data` 使用同一结构，并符合 [`contracts/run_event_v1.json`](../contracts/run_event_v1.json)：

```json
{
  "schema_version": 1,
  "event_id": "uuid",
  "run_id": "uuid",
  "seq": 3,
  "type": "retrieval.completed",
  "occurred_at": "2026-10-05T00:00:00Z",
  "data": {}
}
```

当前事件类型包括 `run.created`、`task.queued`、`task.leased`、`run.started`、`retrieval.completed`、`answer.delta`、`task.retry_scheduled`、`message.completed`、`run.succeeded`、`run.failed` 和 `run.cancelled`。同一 Run 的 `seq` 严格递增，Event 只追加不更新。

SSE 每条消息使用 `id: <seq>`、`event: <type>` 和 JSON `data`。客户端重连时优先发送最后收到的 `Last-Event-ID`；服务端将其作为 `after_seq`。客户端必须按 `seq` 去重，并只在 `run.succeeded`、`run.failed` 或 `run.cancelled` 后结束观察。断开连接本身不表示取消。

PostgreSQL 是 Event Journal 的事实来源。Redis 仅用于通知“可能有新事件”，通知丢失时数据库轮询仍应补齐事实；前端不得依据 Redis payload 或本地状态宣布终态。

## 4. 文档和索引

| 方法 | 路径 | 请求 | 成功响应 | 说明 |
| --- | --- | --- | --- | --- |
| `POST` | `/api/v1/documents` | `multipart/form-data`，`file` | `201`，Document 摘要 | 支持 `.txt`、`.md`、`.docx`；上传后创建 `index_document` Task。 |
| `GET` | `/api/v1/documents` | 无 | `200`，`{"documents": [...]}` | 返回当前 owner 的文档元数据和索引状态。 |
| `POST` | `/api/v1/documents/{document_id}/index` | 无 | `200`，`task_id`、`document_id`、`state` | 创建或复用该文档的未终态索引 Task。 |

上传限制为 10 MiB；扩展名和 MIME 必须匹配。文档状态为 `uploaded`、`indexing`、`indexed` 或 `failed`。Demo 的 `active_index_batch_id` 是内部候选索引批次，不是完整项目的公开 `DocumentVersion`，也没有独立的审核/发布 API。

## 5. 健康检查

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/health/live` | 仅确认 API 进程存活，返回 `{ "status": "ok" }`。 |
| `GET` | `/health/ready` | 返回数据库依赖标记、Redis 降级状态和 Worker 数量；Demo 中数据库由迁移服务作为启动硬依赖，Redis 通知不可用时可为 `degraded`，不代表 PostgreSQL 事实丢失。 |

## 6. 兼容与变更规则

1. 新增字段优先保持向后兼容；改变状态、字段含义、Event 类型或终态语义时，先更新对应 PRD/ADR 和契约。
2. 破坏性接口变更使用新的 API 或契约版本，不在旧路径上增加隐式双读双写。
3. Event 的 `schema_version` 与 JSON Schema 同步递增；旧 Event 必须仍可按原版本补放，除非有明确迁移方案。
4. 前端类型、API client 和 SSE 解析器必须与本文件及 `contracts/` 同步；手工维护的重复接口表不具有权威性。
