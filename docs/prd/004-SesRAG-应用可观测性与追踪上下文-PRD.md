## 1. 需求定位和预期结果

本轮使应用能够回答“请求是否异常、后台任务是否积压、时间花在哪个阶段、一次请求与之后的Worker执行如何关联”。交付的是**产生正确、安全、可采集遥测的应用能力**；Grafana、Prometheus、Loki、Tempo、Alloy的搭建、存储、仪表盘与告警执行由后续ADR-005负责。

| 目标 | 预期结果 | 完成判定 |
| --- | --- | --- |
| O4-G1：可抓取指标 | API与Worker提供各自的内网`/metrics`；短HTTP、Worker状态、队列、物理尝试与阶段耗时有明确口径 | 真实应用操作引起预期序列变化；无流量、未知、缺失与零值可区分 |
| O4-G2：日志可关联 | API与Worker输出统一安全JSON日志，并按当前执行上下文带真实追踪及业务身份 | 可从受控请求、Task、generation关联日志；不存在伪造trace_id或敏感正文 |
| O4-G3：异步追踪不断关联 | HTTP、入队、Worker尝试、关键阶段与下游调用可按冻结的传播约定关联 | 跨等待、自动重试、Worker重启仍有可信来源；各次尝试可区分，不长期保活一个span |
| O4-G4：观测失败不改变业务 | 观测接收端不可用、缓冲满、日志处理失败时，原有业务事实与租约语义保持 | 故障验收能证明业务继续按原规则运行，诊断及退出有界 |
| O4-G5：向005可交接 | 指标、日志、OTLP、运行配置与部署身份有版本化交付依据 | ADR-005的G1～G5逐项有应用侧证据，不要求本轮已能在Grafana查询 |

优先级：P0为业务不变量、安全、跨进程关联或接入必需项；P1为本轮完整交付需要完成的诊断与质量能力。P1不等于可任意跳过。生产SLO、精准审计及遥测零丢失不属于本轮承诺。

## 2. 已确认的需求选择

| 确认项 | 已接受的边界 |
| --- | --- |
| Q1 观测范围 | 覆盖现有v1/v2/v3 API与四类Task，以及聊天、文档入库／重建、检索诊断和下游调用边界；不做浏览器插桩或基础设施Exporter |
| Q2 暴露位置 | API与Worker各有独立指标监听端口，路径为`/metrics`；默认不发布宿主端口、不经前端代理、不加入原业务监听端口 |
| Q3 默认与降级 | 安全JSON日志和内部指标默认启用，指标可显式关闭；traces默认关闭，配置受控接收端后显式启用；观测运行故障不使业务readiness失败 |
| Q4 验收边界 | 本轮用独立测试工程、受控下游与轻量OTLP捕获器验收；不要求真实付费模型／MinerU成功，不部署005整栈 |
| Q5 统计口径 | 到时待领取积压与运行、退避、外部等待分开；尝试结果不混为业务成功；进程计数可重启归零，不承诺精确审计 |
| Q6 追踪连续性 | 新Task保存受限来源，各attempt/generation独立执行片段；幂等不覆盖来源；主动重试产生新来源；旧任务明确缺失；拓扑由ADR-004冻结 |
| Q7 采样 | 显式启用后，本地小流量默认100%，比例可配置；验收100%；未采样不抑制指标／安全日志，不承诺所有错误都有已存trace |
| Q8 信任与隐私 | 默认服务端建立来源，不接续公网传入的追踪上下文；只内部传播，不向第三方注入追踪头；使用遥测字段白名单 |
| Q9 质量定位 | 本地小流量、有界、可诊断；对比资源与延迟开销；具体数值门槛在ADR-004实施前冻结，不宣称生产SLO |

以上为需求层决定。具体SDK组合、指标名称、端口号、表／列结构和传播拓扑由ADR-004冻结并已实施，仍以其及正式接口/契约为准。

## 4. 实施范围与非目标

### 4.1 本轮范围

1. API／Worker应用身份、观测配置、SDK生命周期、内部Prometheus pull端点与安全JSON stdout。
2. HTTP及SSE的边界观测，Worker本次执行及聚合readiness区分，队列快照、尝试结果、阶段和下游调用观测。
3. 新Task可信来源的受限持久化及迁移，跨领取、等待、重试、取消和重启的上下文管理；不变更RunSnapshot或Event协议承载遥测。
4. OTel traces通过OTLP HTTP/protobuf主动发送，选择性自动插桩与安全手动边界；日志不重复走OTLP，指标不重复push。
5. 版本化应用观测契约、运行配置说明、ADR-005交接依据及本轮独立验证要求。

### 4.2 明确不实施

- `docker/monitoring/`及Grafana／Prometheus／Loki／Tempo／Alloy运行组件、面板、存储、告警评估／通知；这些属于005。
- windows_exporter、Node Exporter、cAdvisor、数据库／Redis Exporter、云托管平台与CI基础设施。
- 浏览器SDK、前端页面新面板、对外trace查询接口、客户端可指定遥测终态或trace来源的业务参数。
- 泛化的所有SQL／Redis命令自动插桩、SQL参数／语句正文、请求／响应正文采集；不要求看见第三方服务内部span。
- OTLP logs／metrics、remote-write、exemplar、service graph、metrics-generator、tail sampling、profiling或eBPF。
- 遥测持久发送队列、零丢失／exactly-once、精确计费／审计统计、生产SLO、高可用和24小时独立可用性保证。
- 将`trace_id`写入Message、RunSnapshot、业务Event或前端状态；为旧历史伪造原始trace或回写既有事实。
- 修改或扩展`tests/sesrag-persistent-session-workspace-test/`、`tests/sesrag-rag-mineru-test/`等既往正式验收工程。本轮独立组织测试；可维护受影响的底层单元／接口／迁移回归。
- 修复PRD-003的真实模型计数、额度、解析效果或其它非观测问题；受控替身成功不使既往受限项自动关闭。

## 5. 核心对象、含义与关系

下列是职责和字段类别约束，不预设新增数据库实体或厂商SDK类型。实际结构由ADR-004决定，稳定术语仍以`CONTEXT.md`为准。

| 对象／概念 | 含义与主要职责 | 主要信息 | 关系与边界 |
| --- | --- | --- | --- |
| 应用观测契约 | 向采集方声明观测信号与运行方式的版本化约定 | 契约版本、服务／环境、指标类型与单位／labels、日志字段、传播和配置语义 | 由正式接口说明及版本化契约维护；005部署实例描述只引用，不另立语义真源 |
| 运行观测配置 | 控制本进程生成、抓取与导出行为 | service、environment、启用开关、指标监听、OTLP接收地址、采样比例、各类限额 | API与Worker分别生效；无客户端覆盖，不属于冻结的模型／检索配置 |
| Task追踪来源 | Task入队时的最小可信来源，便于之后恢复关联 | 传播版本、有效trace/span身份、采样语义、来源存在／缺失说明 | 创建时与Task同事务，后续不可因领取／重放覆盖；不保存baggage、凭据或任意请求头 |
| 本次执行观测上下文 | 一个请求或一个Task attempt/generation的临时关联 | 当前trace_id／span_id／采样状态；适用的thread/run/task/worker、attempt／generation等安全身份 | 在并发协程、线程、流及异常退出间正确隔离；不是长期Run Context或新增业务事实 |
| 队列／readiness观测快照 | 对既有状态的有界只读投影 | 观测时间、有效性、队列分组数量、最老等待、PG／Redis与心跳状态 | 不能驱动领取／取消／终态；过期及未知不得表示为健康或空队列 |
| Task尝试观测结果 | 本次已领取执行片段的结束分类 | 有限result、稳定error_code、耗时、执行身份 | 自动重试或让出不创建新Run；进程崩溃可缺结束观测，不能补造成功 |
| 遥测导出状态 | 描述观测本身是否被采样、缓冲、拒绝或发送失败 | 受控错误分类、排队／丢弃数量、最近状态、flush结果 | 不等于业务状态；日志有trace_id不保证接收端存储了该trace |

关系为“HTTP处理→创建Task及受限来源→领取得到本次执行身份→产生阶段／调用观测→按真实结果结束本次执行”。同一Task可有多代执行；Run／IndexBuild等业务身份始终独立于trace身份。RAG Trace仍是RetrievalExecution的安全业务投影，不转换成Tempo存储记录，也不把业务execution_id当trace_id。

## 6. 关键行为与接入语义

### 6.1 三信号和默认行为

| 信号 | 本轮出口 | 默认 | 故障边界 |
| --- | --- | --- | --- |
| 指标 | API与Worker各自独立内网端口的`GET /metrics`，兼容Prometheus文本抓取 | 启用，可显式关闭；不发布宿主端口、不经前端代理 | 端点活着不代表依赖健康；抓取不触发下游模型调用或业务写入 |
| 日志 | 单行安全JSON stdout | 启用；敏感正文采集始终关闭 | 处理器失败不得抛回业务；只输出限频安全诊断，不能无限递归记录日志失败 |
| traces | OTel SDK→明确配置的受控OTLP HTTP/protobuf接收地址 | 关闭；显式启用后本地默认100%采样，比例可配置 | 无接收端、超时或队列满可以丢遥测；不阻塞领取／心跳／业务提交 |

未配置traces时不尝试连接隐式localhost或公网默认服务；无效出站地址不自动改投其它目的端。启用时的合法配置与部署预检可拒绝错误接线，运行中的遥测降级不能改变业务readiness。默认内部指标监听绑定失败须有安全可见诊断，业务继续按原规则运行，部署验收则判观测缺口；指标正常关闭时也不能假称005的G2已满足。

首轮支持现有每容器单API进程、每Worker容器单进程。可启动多个Worker，但每进程指标须有独立可发现目标；不承诺Uvicorn多进程共享registry。重复初始化／关闭、多次create_app及测试隔离不得重复注册或跨实例串数据。

### 6.2 指标语义和统计边界

下表沿用ADR-005的逻辑绑定，不直接作为metric名称。具体名称、完整label值、经典histogram桶、必需初始化序列和样例已按ADR-004落入正式接口及版本化契约。

| 逻辑绑定／补充类别 | 类型、单位与维度 | 必须满足的含义 |
| --- | --- | --- |
| `HTTP_REQUESTS` | counter；有限method、路由模板、status_class及连接类别 | 响应状态与业务任务结果分开；不带原始路径／query，未知路径归固定类别；SSE握手单列，不计入普通短请求错误率样本 |
| `HTTP_DURATION` | 经典histogram，秒；有限method／路由模板 | 记录普通短HTTP请求耗时；SSE长连接不混入该口径；指标／健康探测不污染业务延迟面板 |
| `WORKER_READY` | gauge，0／1，另有已知性／新鲜度投影 | 绑定既有API对Worker心跳可见性的聚合语义：可信探测且可见Worker时为1，可信零个时为0；不可判断时不能为1，也不能把返回200当ready |
| `QUEUE_LENGTH` | gauge，任务数；有限task_kind，应用级快照 | 只统计有效、已到调度时间且尚待领取的queued任务；不包括运行、尚在退避或等待外部服务；不因当前容量槽满就隐藏等待任务 |
| `QUEUE_OLDEST_WAIT` | gauge，秒；与QUEUE_LENGTH相同范围 | 从任务进入本次可调度等待的时间计算，到时无等待为0；不是从最初上传时间累计，不把MinerU解析时间伪装成Worker堵塞 |
| `TASK_ATTEMPTS` | counter；有限task_kind／result | 已领取的物理执行片段按实际结果分类，不按handler正常return或日志success判断整个任务成功；重启可reset，硬杀可缺结束观测 |
| `STAGE_DURATION` | 经典histogram，秒；有限stage／task_kind及结果类别 | 定义明确的阶段耗时；现有毫秒计时正确换算；整体attempt与子阶段分开，不重叠冒充可相加的完整Run耗时 |
| 队列分组与有效性 | gauge及观测时间；有限state／来源 | 另有运行、retry_waiting、waiting_external等投影；保留未来调度与到时待回排的区别，依赖未知／快照过期可见 |
| Worker本进程状态 | gauge／counter；有限状态及操作 | 区分本进程启动、停止领取、租约／调度故障与API所见聚合心跳；进程ID只作目标身份，不作为任意高基数业务label |
| SSE与下游诊断 | 有界counter／histogram | SSE连接／关闭／流错误另列；下游按受控操作、结果／安全错误类别观测，不以原始URL或上游动态消息分组 |
| 遥测自身状态 | 有界counter／gauge及安全日志 | 能判断采样、导出失败、拒绝、丢弃或无法精确计数；不填造SDK未提供的准确丢失数 |

应用级队列与聚合readiness由一个明确的逻辑来源暴露，默认放API侧；Worker端提供自身counter／阶段观测，不重复暴露可被直接sum的全局快照。部署契约明确目标与聚合方式；未来多API实例不能简单sum同一数据库快照。

“有效queued”的取消、deadline、尝试预算、关联业务状态与调度时间条件必须与既有调度规则核对，由ADR-004列成可测试选择谓词。容量暂时不足的任务仍是积压；尚处retry_waiting／waiting_external而未由调度器回排的任务，使用独立分组显示，不能悄悄重算为已领取或最终失败。

只读快照有固定刷新频率、查询时间预算与缓存，抓取不持业务锁、不调用领取／回收器、不逐次全量加载Task。首次未取得或过期／依赖错误时，业务数值不得伪造为0；具体保留旧值或停止暴露由ADR-004统一选定，但必须伴随有效性和时间信息，并在采集契约中规定阈值查询先校验有效／新鲜。依赖正常且队列确实为空时才初始化为0。

### 6.3 尝试、阶段、SSE与错误语义

| 事件／情形 | 观测要求 |
| --- | --- |
| 正常提交任务成功 | 根据本代有效提交或明确结算结果记录成功；不能用已清空lease的ORM状态反向授权写业务 |
| 失败并安排重试 | 本次尝试失败与“后续安排重试”分别表达；不把retry当新Run，也不重复累计一次结束 |
| 正常外部等待／阶段让出 | 本次片段为yielded等有限分类，Task仍未终态；不增加失败次数或成功任务数 |
| 用户取消／正常停机释放 | 分别标记取消或释放；不统称模型失败、HTTP5xx或队列错误 |
| 失租／旧代拒绝／结算未知 | 明确本地执行停止或结果无法确认；不能替新代记成功，不能因观测查询失败重做业务提交 |
| 进程硬杀 | 可能缺span结束及counter；后续领取仍有原来源，不能事后假造旧进程完整结束span |
| 检索为空／受控rerank降级 | empty与degraded分开；基础设施失败保留稳定错误分类，不伪装成没有知识 |
| SSE握手后异常或客户端断连 | HTTP200仅代表握手；流关闭／异常另记，后台Run按持久事实继续；不改取消语义、不逐Event／token生成span |

同一次已确认结束的执行片段只记一次互斥result；失败后是否安排重试可以另有有限标记，但005计算失败attempt增量时不能把“失败”和“安排重试”重复相加。完整业务Run／构建耗时如另提供，必须有单独定义，不由各次attempt耗时求和冒充。

阶段及下游观测覆盖受控边界：模型生成、Embedding、rerank、MinerU提交／上传／轮询／下载，以及本地解析、切片、检索、拼接与发布等关键阶段。流式生成只在固定边界计时／建span，跨协程anext或线程执行要正确传递与清理上下文。详细span目录由ADR-004冻结，不无限包裹每次heartbeat、DB轮询或chunk。

### 6.4 追踪来源和生命周期

traces启用时，新Task的最小可信来源与Task在同一创建事务中保存，不能先提交业务、再依赖第二次观测写入才获得可恢复关联。来源构造／校验失败按受限缺失处理，不能让OTel对象序列化错误阻止业务；数据库事务本身失败仍按既有业务错误处理，不能用“遥测旁路”吞掉真正的提交失败。

| 场景 | 必须保持的关系 |
| --- | --- |
| HTTP创建Task并成功提交 | 请求、入队及随后执行可按冻结拓扑关联；本地生成来源，不保存公网传入任意头 |
| 创建事务回滚 | 不存在已持久化Task来源；已产生span只能表示创建尝试失败，不能宣称入队成功 |
| 幂等重放 | 当前HTTP请求仍可观测，但不重写原Task来源、创建第二Task或第二个业务入队成功事实 |
| 自动重试／外部等待后领取 | 保留创建来源，使用新的attempt／generation执行片段；不让旧执行片段继续接收新一代日志 |
| Worker重启／租约回收 | 根据可信已存来源恢复关联；已丢失遥测不补造，当前业务状态仍由PostgreSQL决定 |
| 用户主动retry／regenerate | 沿用原有新Run／Task语义，绑定当前请求的新来源；可保留安全的父业务关联，但不覆盖旧来源 |
| 旧Task或关闭追踪时创建的Task | 来源可以缺失；若后续启用，创建本地新执行上下文并标明原来源缺失，不能伪称找回原trace |
| 格式错误／未知版本来源 | 受限校验、诊断、按缺失处理；不崩溃或影响租约，不把坏值作为有效trace导出 |

每个请求／执行片段有有限生命周期；Task等待期间不保留一个开放span。具体选用同trace父子还是新trace＋span link由ADR-004选定并给出协议验收。PRD不承诺所有尝试都显示在同一个trace页面；必须能通过来源身份、link及安全业务身份解释关联。

采样决策必须随冻结的传播策略保持可解释，不能在重试时随机重写创建来源。traces关闭或未采样时指标、日志仍产生；有有效未采样上下文可记录真实身份及`trace_sampled=false`，完全未建立上下文时应为空／明确disabled，不能用run_id、零值或随机字符串冒充已导出的trace。采样为100%也不保证崩溃／发送故障时零丢失。

### 6.5 安全日志和信任边界

应用自有日志统一为单行JSON，至少包括契约版本、时间、level、service、environment、稳定action／安全message、适用的trace_id／span_id／采样状态，以及适用的thread_id、run_id、task_id、worker_id、generation、attempt、document_id、index_batch_id、parse_job_id、retrieval_execution_id等安全关联。当前Worker已有其中部分业务字段，thread_id及统一追踪字段等仍需补齐。并非每条日志都必须有全部业务身份，不适用时为空或按契约省略；仅为补充日志字段而进行的对象查询也必须有界。

service身份、environment及采样／来源缺失语义必须与OTel resource、指标目标和005部署描述一致。业务身份只放安全日志／trace属性，不进Prometheus高基数label。trace_id与span_id只能来自当前有效上下文；日志存在不证明相应trace已被接收或尚在保留期内。

默认不接续外部`traceparent`，不接受任意`tracestate`或`baggage`；入口由服务端建立可信根。模型、MinerU、CDN及其它第三方请求不自动注入W3C头，重定向也不能重新带出上下文。安全手动调用span可表示本地调用，不代表对方支持分布式追踪。OTLP发送器本身须排除插桩，避免递归导出。

禁止采集Prompt、消息／文档／检索正文、原始文件名、Authorization／Cookie、API Key、数据库DSN、完整URL／签名query、SQL语句及参数、原始异常文本／traceback和宿主路径。保留有限操作名、路由模板、状态码及稳定错误码。自动插桩必须在产生／处理阶段限制字段，不能先导出敏感内容再指望Alloy清洗；Uvicorn访问日志和SDK／httpx等库的默认输出也要审计。
