## 1. 需求定位与预期结果

本轮把现有文本入库／召回的Demo演进为可选择知识范围、观察阶段、追溯证据的文本RAG。九种输入固定分流：txt/md仅本地结构解析；doc/docx/pdf/xls/xlsx/ppt/pptx原文件通过MinerU精准API解析为Markdown／JSON，再归一化、切片及入库。不将txt/md转为DOCX，不为办公文件提供本地或格式转换回退。只读`rag.search`工具承接检索，持久会话负责Run、消息、流式输出及恢复。

办公文件上传／重建每次确认完整原文件外发，失败即本次构建失败，保护旧active。MinerU不是txt/md的依赖，却是七种办公文件新入库的必要依赖；服务不可用时这些格式不可用，不能用本地文本成功替代办公验收。Embedding／向量库／生成另有依赖。

v1.2取代v1.1的三格式可选增强、DOCX桥接、本地回退及PDF留后续规则；保留原章节和46项功能／12项非功能编号。以下目标与验收口径不因工程实现存在而降低；当前交付及限制见PR-003。

| 目标 | 可判断的预期结果 |
| --- | --- |
| G1：固定路由及真实解析结果 | txt/md不访问MinerU；七种办公格式仅MinerU、逐次授权；不支持格式拒绝。失败／超时／未知提交／取消不转本地、不伪装成功。 |
| G2：形成完整检索链路 | 结构化切片、元数据、真实 Embedding、pgvector 数据库内 Top-K、可选真实 rerank、邻近 Chunk 拼接和生成上下文预算串联起来。 |
| G3：检索可受控装配 | 通过版本化只读 `rag.search` 定义与绑定接入既有 Run；关闭后不访问检索服务，开启后不绕过既有消息和执行事实。 |
| G4：保证一致性和可追溯 | 候选构建失败不影响当前索引；新协议 Run 固定检索配置及语料视图；重建后已有回答引用仍能关联原批次和实际使用片段。 |
| G5：失败和外部风险可识别 | 外发前授权；状态、截止、取消、未知提交结果、解析故障、向量故障和重排故障都有明确语义及安全诊断信息。 |
| G6：形成独立验收依据 | txt/md本地、七种办公格式各自真实云端、故障恢复、真实Embedding/rerank及标注集分别取证；外部受限逐格式列明，不维护上一轮验收工程。 |

优先级含义：P0 为正确性、安全性或主链路门槛；P1 为本轮完整交付必须完成的功能与可用性要求。本文没有以 P2 隐含纳入的“可选半成品”；非目标和后续路线单列。外部凭据不足不改变需求状态，只能使相应验收标为受限，不能宣称全部通过。

## 2. 当前实现基线与本轮差距

以下保留需求确认时的v0.2代码基线和本轮演进目标，不是实施后状态表。工程交付时`pyproject.toml`和`frontend/package.json`已升级为`0.3.0`；实际落地、验证和差异以PR-003为准，既往验收不直接计入本轮。

| 领域 | 当前实际实现与代码依据 | 本轮需要演进的部分 |

| 上传与索引入口 | `backend/application/documents.py::create_document/create_index_task` 仅允许 `.txt/.md/.docx`，单文件10 MiB，记录hash、Document和索引Task；`backend/api/routes/documents.py`提供v1上传、列表及重新索引。 | 九格式白名单与固定路由；办公文件逐次授权、失败不回退；增加知识归属、构建详情和有界诊断。 |
| 本地解析 | `backend/infrastructure/rag/parsers.py::parse_document/SubprocessParser` 解析 txt/md 行和 docx 正文段落，具有子进程及输入／展开／时间限制。当前 docx 不是复杂表格、图片或 OCR 解析器。 | 新写入仅txt/md本地结构解析；已有基础DOCX解析不作为新路线或兜底。另接异步MinerU、结构块及产物身份。 |
| 切片 | `backend/infrastructure/rag/chunker.py::chunk_text`默认按800字符窗口、120字符重叠切分，保存seq和字符区间。 | 增加本地／云端结构优先切片、超长块拆分、Embedding输入限制和标题／源行段／块映射；定义邻近拼接与去重。 |
| 领域协议 | `backend/domain/ports/__init__.py` 已有 `ParserPort`、`EmbeddingPort`、`VectorStorePort` 和 `Evidence`，没有工具定义／调用协议或 Rerank Port。 | 在既有 Port/Adapter 边界演进，不让路由、ORM 或 Vue 页面承担检索规则。 |

| 向量检索 | `backend/infrastructure/rag/pgvector_store.py::search_chunks` 取 owner 下 active batch 的 Chunk，在 Python 计算 cosine、排序再截 Top-K。pgvector 当前主要用于存储。 | 将授权范围、批次、空间与过滤条件纳入数据库查询，在 PostgreSQL 内做距离排序和 LIMIT；增加 rerank 和检索轨迹。 |
| 索引发布与历史 | `backend/workers/handlers/index_handler.py::process_index_task` 已把候选计算放事务外，并在租约／代数保护下短事务发布；`PgVectorStore.replace` 会删除该 Document 的旧 Chunk，再插入新批次。 | 保留有效执行者和原子发布机制；持久化 IndexBuild，保留被视图／引用依赖的旧批次。当前旧 Chunk 删除行为不足以支持本轮历史片段读取。 |

| Run 内 RAG | `backend/application/session_runs.py::new_snapshot` 冻结检索开关、Top-K 和 Embedding 配置；`backend/application/session_execution.py::process_session_run` 直接检索、记录 `retrieval.completed`、生成 ContextPlan 后调用模型。 | 用受控检索工具替代新协议的直接调用；增加完整检索策略及批次视图冻结，保留 ContextPlan 和最终回答事务不变量。 |

## 3. 官方调研对需求的约束

完整原始依据见[调研附件](003-SesRAG-RAG与MinerU-调研依据.md)。本次只读取官方公开资料，未申请 Token、上传文档或调用真实解析／模型服务。

| 已核实事实或未确认事项 | 本轮采用的产品约束 |
| --- | --- |
| [MinerU 官方精准 API](https://mineru.net/apiManage/docs) 使用 Bearer Token；免 Token 的 Agent 轻量 API 为另一产品，输出及限额不同。 | 本轮接入精准 API，不在凭据缺失时静默切轻量版，也不将自托管 MinerU 作为已交付替代路线。 |
| 官方精准API列出doc/docx/pdf/xls/xlsx/ppt/pptx；未列txt/md输入，Markdown／JSON是默认输出。 | txt/md只本地；七种办公格式原件直传，不转换或回退。官方支持不等于项目已逐格式联调／验收。 |
| 本地文件需先申请上传 URL，PUT 字节后上游自动提交；URL 提交接口不是文件上传接口。 | 采用官方本地文件流程，Token 只发送给 API，不能转发到签名存储地址；不再对同一上传额外创建一次解析任务。 |
| 上游状态含等待上传、排队、解析、转换、完成和失败；成功 HTTP 之外仍需检查业务 `code=0`。 | `done` 只表示远端解析完成，只有本地索引发布成功才能显示可检索。 |
| 精准版当前上限为 200 MB／200 页；批量概要写 200，具体接口写最多 50 个。 | SesRAG 使用更小的自有限额和逐文档处理；适配器如内部合批，单请求不得超过 50，并在 ADR 核对真实服务。 |
| 上传 URL 有效 24 小时；结果 URL 有效期和结果保留时间未查明。 | 不将 24 小时套到下载结果上；完成后尽快安全物化必要结果，不承诺远端永久可取。 |
| 每日 1000 页为最高优先级额度，不是固定总页数上限或完成时限承诺。 | 额度和排队时长作为账户／外部条件报告；不保证官方未承诺的 SLA。 |
| `data_id` 为身份回传，未承诺上游请求幂等；也未确认可用的远端取消 API。 | 明确提交结果未知和本地取消边界；不声称重复提交无成本或本地取消已经停止远端处理／计费。 |
| 云端说明的`full.md/layout.json/*_content_list.json`与链接的开源4.0输出文件及Schema不完全一致。 | ADR用七种办公格式真实样本固定Markdown／JSON识别；无有效文本／不安全／整体协议不支持则失败。原PDF页、幻灯片／工作表与Word派生分页区分，缺失来源明示。 |
| [pgvector 官方说明](https://github.com/pgvector/pgvector)支持默认精确检索；ANN 的召回、过滤和维度限制另有条件。 | 本轮选择数据库内精确 cosine 检索作为正式基线。ANN 不作为本轮必需项；不把向量存储上限当 ANN 索引上限，也不把算法精确召回等同于问答准确率。 |

## 4. 产品范围、边界与非目标

### 4.1 本轮范围

1. 最小逻辑知识库：创建、列表、改名、启停、选择一个知识库进行本次检索；同 owner、同知识库只绑定一个 EmbeddingSpace。既有文档的归属迁入该 owner 的默认知识库，旧向量是否可信可用另按 §7.6 判断。
2. txt/md只本地结构解析；七种办公格式只MinerU精准API，逐次确认外发，失败不回退。PDF扫描文字在MinerU能力内识别，不等同多模态RAG或任意扫描件质量保证。
3. 解析产物归一化、结构优先切片、元数据、真实 Embedding、pgvector 精确候选召回、可选真实 rerank、邻近片段拼接和 ContextPlan 预算控制。
4. 服务端版本化配置与只读 `rag.search` 工具装配；工作台提供受支持的配置选择、解析／构建观察、检索诊断和证据查看。
5. 候选批次原子发布、历史证据保留、Run 检索视图冻结、故障／重启恢复、受限出站及安全清理；为本轮独立验收明确证据要求。

最小知识库用于解决“检索哪些文档、使用哪个向量空间”，不承诺知识治理平台。停用表示拒绝新上传、重建及新检索视图；已冻结的视图和历史引用仍可由原 owner 读取、继续执行，除非发生权限撤销或配置安全禁用。它不是立即撤回历史事实的删除操作。

### 4.2 本轮不实施

- txt/md云端解析、DOCX桥接、办公文件本地解析／本地PDF页数探测、Office转PDF等转换回退、自托管MinerU；未来替代解析须另行确认。
- 通用 Agent、多工具自主规划／循环、任意代码执行工具、MCP 市场、外部工具写操作和完整 Capability/Guardrail 平台。只交付 `rag.search` 所需的受控工具子集。
- 任意URL／网站／目录抓取、远程盘同步、HTML、独立图片／音视频，以及docm/xlsm/pptm等白名单外扩展名；其他MinerU格式不自动成为项目范围。
- BM25、稀疏向量、Hybrid/RRF、多路融合、自动合并树、跨知识库联合检索、查询改写和多轮检索规划。
- Milvus 等新向量数据库、分布式向量集群、强制 ANN／GPU、本轮内的全量模型服务运维平台。
- 文档内容原地更新、跨知识库移动、硬删除知识库／文档的用户入口、审核发布回滚工作流及完整 Document Version 生命周期。重新上传变化后的源文件创建新 Document；同一不可变源可重建 IndexBuild。
- 完整排版还原、OCR／表格／公式百分之百无损、Excel公式计算／刷新、宏执行、文档编辑、视觉问答、精确PDF高亮阅读器、隐藏思维链、生产级认证及SLO。只使用解析文本，不以返回值存在证明计算正确。
- 修改、扩展或重新统一上一轮 `tests/sesrag-persistent-session-workspace-test/` 验收工程。本轮后续独立建测试方案及目录；现有底层单元／契约测试可随受影响代码维护，不能借此把旧验收套件纳入本轮。

## 5. 用户与操作者流程

### 5.1 文档入库

用户选择启用知识库，单次上传九格式之一。txt/md显示本地解析，不要求云端授权；办公文件显示“MinerU云端解析，失败不回退”，每次上传／重建须确认完整原件（可能含图片、元数据及隐藏内容）外发，不沿用上次同意。取消授权不提交。服务端已知关闭／配置缺失／能力不可用时即时拒绝办公新构建，不创建远端任务；txt/md及旧历史仍可用。

后台确定失败、无有效文本、超时或提交未知均不能转本地；页面显示安全原因和处理方向。解析、切片、向量化、发布全部完成才可检索；新构建失败／取消保护旧active。“远端done”不等于“已发布”。

### 5.2 对话检索

用户在发送消息前选择“关闭 RAG”或一个知识库和受支持的 RetrievalProfile，可在服务端允许范围内调整 Top-K、重排开关和邻近窗口。服务端校验并冻结配置与语料视图，再按既有 Thread/Branch/Message/Run 流程执行。工具产生可追溯候选和最终证据，ContextPlan 决定真正送入生成模型的部分，回答只引用这些内容。

修改工作台配置只作用于后续新 Run，不影响正在执行的 Run。空知识库或过滤后没有已发布批次可产生合法空视图；查询时显示“当前范围无可用证据”，不得把尚在解析的文档当作可检索。

### 5.3 诊断与恢复

操作者可在受权范围输入查询，查看选定视图中的候选、原始向量分数、重排分数、拼接及预算去除原因。诊断只检索，不创建聊天消息／Run，不调用生成模型；与对话使用相同检索能力和限制。重启 Worker 后，已保存的上游身份可继续查询；提交结果未知、凭据失效和配额问题显示明确处理方向，不能伪装成功或无命中。

## 6. 核心对象及关系边界

以下是需求级对象及关键字段，不是数据库表、函数名或完整 Schema 的最终设计。详细存储、事务实现和协议版本由后续 ADR 确认；稳定含义维护在 `CONTEXT.md`。

| 对象 | 含义与主要职责 | 关键身份／字段 | 关系和边界 |

KnowledgeBase 绑定的 EmbeddingSpace 创建后不可直接修改。更换模型空间时新建知识库并重新入库；不在原库中同时混放新旧空间，也不通过修改维度标签假装完成迁移。底层可以共享相同 space 的计算配置，但不能跨 owner 泄漏文档／缓存。

## 7. 关键行为和状态约定

### 7.1 MinerU 异步解析与恢复

路由规则固定为`format_router_v1`：txt/md→local；doc/docx/pdf/xls/xlsx/ppt/pptx→mineru。服务端按已校验格式决定，客户端不能改mode或换解析器；移除可选增强与解析回退。txt/md不查MinerU凭据／健康、不提交云端、不转换格式。

办公文件上传／重建每次须cloud_consent=true及有效consent_version，缺授权422。已知禁用、缺Key／安全配置／支持协议时在登记新Job前拒绝，给出能力不可用原因。获准后使用精准API和有界轮询：登记Job→保存提交意图→申请上传URL并保存身份→PUT原字节→查询同batch→安全下载→归一化。对返回Markdown做本地结构归一化，是云端结果处理，不是办公原件本地解析／失败回退。

Job区分本地解析、云端提交／上传／等待／下载／验证／归一化；成功须有非空有效规范文本和唯一产物。远端done不等于已发布。远端明确failed、读取／转换／解析错误、认证／额度问题、整体协议不支持、不安全／空白输出、独立解析截止均结束本次Job及构建，不切本地、不换轻量API／格式。

同一逻辑工作内保留有界安全网络重试、轮询和断点恢复；正常等待不计Task错误，不跨等待持事务。已有batch重启继续该batch；提交可能已受理而无身份时，以MINERU_SUBMISSION_UNKNOWN结束本地Job／Build，保留remote_outcome=unknown_may_continue，禁止自动重新申请。非幂等提交应答不明不能当普通临时错误盲重发。人工新操作须新幂等键、新Job、逐次授权及潜在重复成本确认，原失败事实不复活。

只保留单ParseJob检查点，不新增双路线ParseAttempt或ParserInputArtifact；Task/generation维护有界物理执行，Job保存上游身份及解析事实。迟到结果不能改已失败／取消的Job或发布候选；云端预算不再预留本地回退时间。失租仅允许新有效代恢复同Job，不授权新提交。

取消停止后续上传、轮询和发布，已上传文件不能声称撤回或远端已停止／免计费。完成竞争由有效身份和短事务裁决，只出现一个本地终态；失败、超时、取消保护旧active。

办公文本验收关注正文、标题、表格和可靠来源；PDF扫描文字限于服务能力。不承诺完整排版、Excel计算、宏执行或编辑。PDF原页、幻灯片／工作表位置仅在真实协议可靠映射时展示；Word云端分页不冒充稳定原页。位置缺失明示，Document／批次／块／Chunk和实际上下文身份仍必须可追溯。

### 7.2 切片、构建与发布

1. txt按行／空行，md按标题／段落／代码／受支持表格形成本地块；办公文件消费MinerU受支持Markdown／JSON，两路共用块与来源映射。结构边界保留、长块有界拆分；不执行HTML／脚本／公式或加载远端资产，缺失结构／位置如实标记。
2. 字符切片参数和 Embedding 模型输入限制同时满足。超长文本在向量请求前明确拆分／拒绝，不能依赖 Provider 静默截断；Overlap、重复页眉处理等策略须版本化，不能在没有记录的情况下改写事实。
3. 候选解析、切片及向量计算在发布事务外完成。IndexBuild 冻结源、解析、切片和向量配置；候选不参与正常检索。发布时验证 Task/worker/generation/lease/deadline 及 Document 所属关系，再原子切换 active 指针和完成状态。
4. 同文档至多一个活动候选构建；同一操作重复请求返回原构建或明确冲突，不并发写两个“当前候选”。重建失败或取消不清除原 active。成功历史批次与其证据不可原地更新。
5. 保留 active、RetrievalView、ContextPlan、Citation 正在引用的批次和必要产物。无引用候选、下载 ZIP、解包临时目录按有界保留规则清理；不能为节省空间删除仍被历史回答引用的片段。完整源、产物及历史增长必须有容量提示和操作者清理机制，但用户硬删除入口不在本轮。

### 7.3 检索、重排、拼接与冻结

检索顺序固定为：服务端授权／校验视图 → 生成同 EmbeddingSpace 的 query 向量 → pgvector 在所选批次及元数据范围内精确召回 `candidate_k` → 可选 rerank → 选取 `top_k` 个命中 → 同文档同批次邻近扩展／重叠去重 → 按生成模型预算形成 ContextPlan → 生成回答和引用。

对话检索的 query 是本次 Run 锚定的用户 Message 原文；本轮不做模型改写、拼接整段对话或自动多次检索。超过该 EmbeddingProfile 声明的查询输入上限时明确拒绝／失败并提示可缩短问题或关闭 RAG，不静默截断问题。诊断入口使用其显式输入的查询，遵守相同校验。

支持的过滤条件限定为 `document_ids`、文件类型集合和标签集合：不同字段之间为 AND，文档／类型集合内为 OR，标签集合表示全部标签均满足。文档／类型集合缺省时不增加该项限制，显式空集合表示空范围；标签集合缺省或为空表示不限制标签。非法值和越权 ID 不忽略。视图冻结的是过滤后的批次集合，后续标签变化不会重新扩展旧视图。

`candidate_k` 是进入重排的最大候选数，`top_k` 是重排后或未启用重排时的最大命中数；它们都不是“必然返回数量”，也不是最终拼接后片段数。合法范围不足 K 时返回实际数量，不补入越权、旧视图外或其他向量空间的片段。并列分数用稳定身份规则排序；dense 分数与 rerank 分数分别保存，不能相加或用同一个无语义的 score 覆盖。

邻近拼接以命中 Chunk 的 seq 为中心，只在同文档同批次内扩展，合并重复字符区间并保留组件映射。增强文本不得无限增长；先按检索策略限制，再受生成模型 ContextPlan 限制。被截断／移除的片段要有可诊断原因；最终引用必须属于实际输入范围。

新协议 Run 在创建时冻结工具定义／绑定、RetrievalProfile、Embedding/RerankProfile 的版本和非 Secret 参数、知识库与规范化过滤条件，并解析成当时已发布的 RetrievalView。之后新增文档、标签变更、重建发布或修改默认值不影响它；后续新 Run 才看到新视图。自动 Task 重试使用同一视图，按新 generation 保存执行轨迹；不保证远端模型输出逐字一致。

用户显式重试／重新生成默认沿用来源 Run 的 RAG 配置及视图；用户若希望用最新知识，发送一条新的用户消息触发新 Run。本轮不增加“悄悄按最新语料重新生成”的分支。视图损坏／缺失、原依赖不可用、运行时权限撤销或安全禁用时明确拒绝／失败，不能静默换模型、换库或改查最新批次。

检索结果语义分开：`off` 是工具关闭；`empty` 是成功执行但范围内没有可用片段；`degraded` 是允许的明确降级；`failed` 是依赖或执行错误。本轮不增加自动无答案分类器或可调相关性阈值，返回候选不表示它必然包含答案。Rerank 启用后默认失败即失败，只有事先冻结的显式 `dense_fallback` 策略才能降级为原 dense 排序并告知用户。Embedding、向量库、授权或视图错误不允许伪装成空检索。RAG 关闭时不调用 query Embedding、向量库或 reranker。

### 7.4 工具、会话与事件

`rag.search` 是应用层注册的只读工具，输入只接受查询、受权范围及服务端允许的参数，输出版本化证据与检索轨迹引用。前端只能选择可用绑定，不能注册工具、指定执行代码、伪造 owner／批次／终态或提交服务地址。

本轮是受控固定流程装配：一次 Run 的每个 Task/generation 至多启动一次逻辑检索 ToolCall；内部网络重试不是新的用户 Run，也不是新的逻辑工具。失败回排后可有新一代调用，但旧执行者不得追加进度／结果。工具成功并不等于 Run 已完成；最终回答、Run 终态及终态事件仍遵循现有事务约束。

工具开始、阶段、结束、失败和降级应形成有界的服务端事实，并由现有 Event Journal/SSE 补放；保留 seq 去重与重连。可以展示“检索／重排／上下文已选择”等关键阶段，不显示隐藏思维链，也不把工具返回中的提示注入当作系统指令。

### 7.6 既有协议与历史数据边界

既有v1/v2请求、响应、事件和历史快照按原版本解码；产品版本v0.3与协议版本分别管理。新块／可靠来源、固定解析路线及工具／视图用新版本表达。旧v1 txt/md写入保留；DOCX上传／重建要求升级并逐次授权，历史仍可读。可靠page等位置仅属新契约；不得改旧严格Schema。具体新增／修改／保留入口由ADR及接口文档逐项列明。

旧 Document 的归属可迁入默认知识库，但“384 维”本身不能证明它们来自同一模型。默认库须绑定迁移时显式选定的空间；只有配置来源可信、经操作者明确确认且与该空间相同的旧向量，才能作为兼容批次供新检索使用。无法确认或与所绑定空间不匹配的文档保留登记、旧事实和现存引用，标记需重建，不能自动混入新空间。旧实现已经删除的片段如实显示不可恢复，需要重新索引才能为后续 Run 产生新证据，不能反向补造原引用内容。

历史 Run 不伪造 RetrievalView、ToolCall 或 PDF 页码，也不改写原冻结模型／检索配置。仍需执行的旧协议 Run 只在能满足其原配置及可信兼容数据的条件下按明示兼容路径执行；不能满足时明确失败及原因，不静默使用新的向量空间。新协议的视图冻结验收从其明确的启用边界开始，不宣称历史 Run 原本已有该语义。

### 10.3 小规模效果、质量与判定

1. 至少20有答案、5无答案，冻结九格式、中英及跨片段标注；每办公格式有真实产物，PDF含文本型及受控扫描文字。以原源答案和可核对块／位置标注；无精确原位置时用冻结规范文本及人工核对范围并注明限制，不造坐标。切片改变重新映射，不硬编码随机Chunk ID，分格式报告遗漏与结构差异。
2. 有答案查询的 dense `Recall@20`（每题相关标注 Chunk 的召回比例，再按题平均）目标不低于 0.85；同时报告有相关证据命中的查询比例。配置／语料／模型和全部失败样本一并保留，未达标必须调整或列失败，不能仅展示成功问题。
3. 同一视图、候选集合和模型配置比较 dense 与 rerank 的 MRR@5、Recall@5；至少有一个预先标注的语义干扰场景能证明真实 reranker 调整排序并提升相关证据名次。不得要求每题单调提升，也不得隐去下降样本。若整体 MRR@5 下降，不能把该配置推荐为默认启用，需分析并调整／保留明确限制；本轮默认关闭不免除真实重排能力验收。
4. 构造答案跨片段的确定样本，证明邻近增强后的 ContextPlan 包含原缺失答案范围；同时验证重复命中去重和预算不足时的去除说明。不能只以“拼接后字符更多”判断增强有效。
5. 确定性断言中，越权／视图外候选数为 0，引用身份和实际上下文范围一致率为 100%，预算越界和候选半发布数为 0。这是本地受控数据的正确性要求，不是生成模型永不出错的保证。
6. 无答案查询用于报告错误引用、无关证据及生成行为，不以“向量一定零命中”判定；本轮没有自动无答案分类器或可调相关性阈值。检索成功但相关性弱与基础设施失败分开记录，回答不得捏造证据，也不能把返回了一段向量近邻当作已找到答案。
7. 性能按 NFR-008 独立测量。工程链、云端等待、Embedding、数据库召回、rerank 和生成分别计时，不把远端排队耗时归为数据库性能，也不使用 Mock 延迟作为真实服务指标。

8. 分格式记录正文／表格／标题提取、可靠位置覆盖、遗漏／变化、切片和耗时；Excel只记录服务返回的文本／值，不证明公式计算正确。办公无本地对照，不再要求txt/md云端增强比较，不用不同视图伪造rerank收益。
