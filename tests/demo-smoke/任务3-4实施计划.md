**编号**：001

**日期**：2026-10-07  
**状态**：当前可验证基线已实施及校审；完整受限目标明确未完成  
**依据**：`docs/当前任务说明.md`、`test-cases.md`、`test-plan.md`、`specific_test_script/README.md`

> 执行方式：按 executing-plans 的检查点推进；独立类别按 dispatching-parallel-agents 分工，最终按 requesting-code-review 和 verification-before-completion 校审。不自动提交。本任务不修改产品实现，不回填任务5结果。

**目标**：为可在本机验证的用例及部分用例的已有子项提供真实断言、中文日志、逐测试点报告，接入隔离环境总入口，并真实试跑一次完整闭环。

**架构**：保留 PowerShell 生命周期入口；分类采用 Node 单文件入口，共享六参数解析、HTTP/SSE、限定本次项目的 Docker/只读 PG 诊断和报告库。纯函数/组件测试调用真实生产代码；无法满足完整条件的子项独立 blocked，不以源码关键字存在替代行为通过。生命周期结束后的断言由总入口清理后专项复核，不能在容器尚存时宣布清理通过。

**技术**：PowerShell 7、Node 24、Playwright、Vitest、Python 3.12、PostgreSQL/pgvector、Docker Compose。

## 边界与文件职责

| 新增/修改 | 职责与使用阶段 |
| --- | --- |
| `lib/category-kit.mjs`、`lib/category-kit.test.mjs` | 分类共享客户端、证据、逐项报告及报告工具自检；分类执行/审批阶段。 |
| `specific_test_script/*-tests.mjs` | 按用例前缀划分的真实分类入口；仅接受既定六参数。 |
| `specific_test_script/*.py`、`*.test.ts`（按需） | 生产纯函数/组件/受控生产函数的测试驱动，不给生产代码加后门。 |
| `specific_test_script/manifest.json` | 分类路径、名称和有界超时，只有有真实检查的分类才 enabled。 |
| `tooling/check-coverage.mjs` | 核对用例—测试点—脚本声明—试跑报告的覆盖和状态，不把 blocked 当已实现断言。 |
| `run-demo-smoke.ps1`、`lib/smoke-common.ps1`（按需） | 总调度及生命周期断言钩子；精确销毁后才能检查 LIFE 结束目标。 |
| `README.md`、分类 README、`test-plan.md`、数据策略 | 说明实际脚本映射、命令、约束和新增驱动。 |
| `任务3-4实施与审批记录.md` | 记录试跑、有效性校审、已落实内容及未满足子项；不是正式验收/缺陷报告。 |

所有业务数据由各用例独立正式 API 创建，不需要全局 SQL 种子。只读诊断不改变 state/seq/generation。容器故障只作用本次 project，分类 finally 恢复服务；环境最终销毁只归总入口。
