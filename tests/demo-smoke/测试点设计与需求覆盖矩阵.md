## 1. 目的、范围和使用边界

本文件回答“需要测什么、为什么测、观察什么结果、当前能否测、实现依据在哪里”，供后续设计具体测试用例，不替代测试方案、用例步骤、分类脚本或执行报告。本轮只新增设计文档和导航，不修复产品代码，不启动测试容器，不创建测试凭据。

测试目标以 PRD/ADR 为标准，实际入口以代码为准。代码缺陷不意味着该需求可以不测，也不能把当前错误行为改写成正确预期。能够通过现有入口观察不符合预期的行为，列为“可验证·差异”；没有完整实现或确定性触发条件的目标，明确列为“部分/暂不可验证”。

覆盖范围包括：25 项编号功能、6 项前端工作台能力、领域关系与状态机、API/Event 契约、Compose 部署、6 项非功能要求、8 条验收标准及必要工程边界。测试基础设施闭环另列为配套质量内容，不冒充产品功能。完整项目的 RBAC、工具、HITL、专用 MQ、知识库审核发布等能力不在本次功能验收范围。

## 2. 类型、状态、环境与判定约定

### 2.1 类型和优先级

表格“类型”使用功能、异常、边界、并发、恢复、安全、权限、契约、性能、架构或运维，并标注优先级：

- P0：持久化事实、唯一身份、终态、租约、取消、索引污染、安全边界及验收关键路径。
- P1：主要交互、错误诊断、配置、可观测性和契约完整性。
- P2：补充工程约束和非目标入口检查。

一个测试点只判断一个目标。一个目标涉及多个字段或原子事务时，这些字段共同构成同一判定，不拆成重复点；不同状态、步骤边界、故障或投影层分别列点。同一测试点可有多个用例数据，不要求把每个输入枚举为新的测试点。

### 3.2 不沿用调研文档中不够准确的表述

- Queue 只有 `queued` 领取和 leased/running 过期回收；`schedule_retry` 写 `retry_waiting` 后没有到期回排代码。退避函数存在不等于重试闭环已经落地。
- 续租/成功/重试等先按条件 SELECT 再赋值提交，不是全部使用原子条件 UPDATE。普通旧 generation 拒绝与 SELECT 后发生接管的竞态是不同测试目标。
- Runtime 的 `run_forever` 等待当前 `run_once` 完成后才执行 `sleep(min(grace, 1))`。不能理解为“运行中任务只等 1 秒”；真实缺口是没有按 20 秒宽限限制当前 handler，停止标志会结束续租循环，失租也没有中止 handler。
- RunSnapshot 虽已保存，但模型值硬编码为 `mock`，Handler 使用 Worker 当前 Settings/Provider，而不读取 snapshot。冻结执行语义尚未闭环。
- 索引 Chunk/active/Document 的提交和 Task succeeded 是两个事务；不可称为 ADR 所要求的全部原子提交。
- ready 的 `database=ready` 是固定值；Redis 标记取决于 client 是否存在，不能证明数据库和 Redis 当前可达。
- 前端 HTTP 使用 `VITE_API_BASE_URL`，SSE 使用相对地址；根 Compose 注入跨端口绝对 API 地址，App 未配置 CORS。前端还有终态消息、状态更新、自动重连、刷新时间线及文档状态自动更新缺口。
- `task.leased` 被契约列出但无生产代码追加；Provider 的 `stream_answer` 实际发送 `stream:false`，只 yield 完整答案一次。Mock 不证明真实 token 流或检索语义效果。

上述是测试设计的代码核对结论，不是本轮动态失败结果。CONTEXT 中的“已实现”和 ADR 的“已实施”不能替代逐点验收。

| --- | --- |
| 直接覆盖 | 测试点直接判断某项功能、行为或验收条件。 |
